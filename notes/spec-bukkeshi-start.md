# 線消 部分消去：線切断寸法の欄・始点・[Enter] の関係（調査メモ）

対象の手順：`type D | type 2 | 430 180 left | type 1 | type 5 | type 2 | 162 140 left | type 5 | key enter | 450 330 left`
実機：[419..330] と [200..139.943]。移植：[419..330] と [140.000..139.943]。

## 結論（測定からの推定。decomp では確認できていない）

y=200 は切断寸法でも前の点でもなく、**段 2（始点指示）での [Enter] が「画面 (400,200) の左押し」になる**ことから出る。

手順の読み：
1. `D`、`2`、`430 180 left`：線（左辺 x=161.973）を拾って段 2（始点指示）。
2. `1`：①線切断寸法 の欄が開く（`ld_ask`、src/cmd.c:5487）。`5`,`2` は欄の文字。
3. `162 140 left`：欄が開いている間の左押しは **欄を閉じるだけで始点にならない**（src/cmd.c:16819。linedel_s1_c1 の測定）。打った `52` は捨てられる（[Enter] で確定していないので ld_cut の値にもならない）。実機でも、あとで切断が起きる以上この読みと矛盾しない。
4. `5`：欄が閉じたあとの数字キーは上段の項目 5。部分消去の段 2 では何も起きない。
5. `key enter`：段 2 のままなので **始点指示での [Enter]**。実機はこれを (400,200) の押しとして扱い、線の足は y=200（線は x=161.973 の縦線なので u は y から決まり、x は無関係）。始点 u0 = 419-200 = 219。
6. `450 330 left`：終点。y=330。間 [200..330] を消す。残り [419..330] と [200..139.943]。実機と一致。

線切断寸法の値（`52` mm × unit_mm 1.744108 = 90.7 など）は一切使われていない。200 と一致する式はない（200-139.943=60.057、419-200=219、330-200=130 は 52・5・1.744108 のどの組合せとも合わない）。

## 移植の差

src/main_wasm.c:6453 の `(command==10 && stage>=2)` の [Enter] は `jw_click(mouse_x, mouse_y, 0)`、つまり最後に押した座標 (162,140) で押す。そのため始点が y=140 になる。
一方、段 3 の [Enter] (src/main_wasm.c:6440) は固定の (400,200)。

実機は段 3 で、直前の押しが (300,350) でも (400,200) を使う（nokori-log.md:712、dfz_D_23・kk_k1〜k4）。他の命令の [Enter] も画面 (400,200)（history-2026-10.md:21、probe_enter.txt の 7 件、「鍵盤の矢の初めの位置」と読んでいる）。実機の [Enter] は最後のマウス位置を使わないので、段 2 だけ別とする理由がない。

## 直し方（提案。コードは触っていない）

main_wasm.c:6440 の条件を `cmd.stage == 3` から `(cmd.stage == 2 || cmd.stage == 3)` に広げ、段 2 でも `jw_cmd_press(&cmd, drawing, &view, 400, 200, 0)` を呼ぶ。6453 の `command==10 && stage>=2` の枝は不要になる。

## 不確かな点

* **decomp では確認していない。** ovl23 の入力関数 `ovl23_0000_input`（dis 0x2ab81〜）や点入力 `FUN_1def_0904` は見たが、[Enter] が (400,200) になる箇所は特定できなかった。「(400,200)＝鍵盤の矢の初期位置」は既存ノートの推定の継承。
* **回帰の危険：dfz_D_23** は `type D|200 300 left|key enter|430 180 left|450 330 left|key enter|…` で、段 2 の [Enter] を含む。今の移植は (200,300) で押しており、nokori-log.md:712 では「D_1・D_7・D_23 すべて実機と一致」とある。広げると D_23 の始点が y=300 から y=200 に変わるので、functest で D_23 を再確認すること（今回はエミュレータを動かしていないので未実施）。D_23 が一致のままなら段 2 [Enter] の差は何か別（たとえば欄を開いて閉じたあとだけ、あるいは直前が欄での押しだったときだけ (400,200)）ということになる。その場合は条件を「`ld_ask` を閉じた押しのあと」に絞る案もあるが、根拠の測定は無い。
* 手順 2 の `430 180 left` が線を拾えている点（利用者は miss と言っていた）。移植は段 2 に入っているので拾っている。実機でも拾えていなければ、そもそも段 2 に入らないので、この読みは成り立たない（が、結果の切れ方からは入っていると読める）。
* 手順 4 の `5` が実機で何もしないこと。
