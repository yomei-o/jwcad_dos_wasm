#### 図形登録（**書けます**。本物のファイルとバイト単位で一致）

`orig/JW_CADV.HLP` が道を書いています（図 形 その1/4）。`sh tools/zukei.sh`
がそれを本物に通して、書き出したファイルを残します:

    図形 → ①登録 → 対角2点（始点が左なら線･円弧･曲線、右なら文字も）
         → 基準点（左は任意点、右は指定点）
         → ①選択確定（この行の桁 32..42）→ ◆図形名入力 → [Enter]
         → `書き込みます |1) 実 行(L)|2) 再選択(R)|`（桁 22..32）→ ①実行

**「①範囲 確定」は押しません。** 対角の 2 点目を右ボタンで取ると、範囲が
決まって**そのまま基準点に進みます**。`tools/zukei.sh` にはその位置
（560,8）を押す行が残っていますが、そのときの行にはセルが無いので何も
起きません —— 原作もこちらも無視するので、道としては同じです。

`sh tools/zukeicase.sh` が本物とこちらを同じ条件で走らせて、画面と**書いた
ファイルの中身**を突き合わせます。両方とも環境変数で動きます:

図面を開いた直後は画面と図面が 1 対 1 です —— **画面 x = 単位 + 121、
画面 y = 463 − 単位**（基準点の分かっている 2 例から実測）。だから図面
(28,80) のものは (149,383) で押せます。

書かれるのは **`A:\ZUKEI_n_\<名前>.JWK`**。グループは 50、各 50 個まで
（HELP）。`ZUKEI_n_` が無ければ作ります。中身は図面（`.JWC`）の記録を
並べ替えたもので、**ヘッダ行は 4 行でなく 2 行**:

| 位置 | 何 |
|---|---|
| 0x00 | `jw_cad(c)sym` ＋ ドット 27 個 ＋ NUL（40 バイト固定。`.JWC` は `jw_cad(c)data` で、ドットの中に旗が混ざる。図形にはその旗が無い） |
| 0x28 | 図面の 0x28..0xC7 をそのまま（図面名 32 バイト × 2 と空白、行末の `\n` まで） |
| 0xC8 | CSV 1 行（下）＋ NUL ＋ 空白、0x18F が `\n` |
| 0x190 | 線 22 ×、円 32 ×、**点 12 ×、文字 24 ×**、文字列プール。**点が文字より前**で、図面（文字→プール→点）とは違う |

CSV の書式は本物の中にあります —— `decomp/ovl/jw01.exe` の 0x4345a:

    %li,%li,%i,%i,%f,%f,%f,%i,%g

順に **線・円・点・文字**の数（図面の 2 行目は線・円・文字・点で、ここも
違う）、下の 3 つ、**文字列プールのバイト数**、**図面の縮尺の分母**。

三つの数は測って出しました（`tools/zukeigrid.sh` で同じ図形を基準点と範囲を
変えながら何度も登録し、`tools/jwkcheck.py` がファイル自身の記録から計算し
直して突き合わせます）:

    s  = 88 / 図形の幅と高さの**長いほう**
    n1 = 4 + s × 基準点より左へ出ている量
    n2 = 4 + s × 基準点より下へ出ている量

幅と高さは**基準点を含めた**外接矩形のもの（原点は必ず中にある）で、円弧は
**描かれている分**だけ（円全体ではない）。10 個のファイルが小数第 6 位まで
合います。紛らわしい 2 例が決め手です:

* 幅 10・高さ 35.4 の図形は `s = 88/35.4`。だから幅ではなく長いほう。
* 四分円だけの図形は `s = 88/四分円の幅`。だから円全体ではない。

つまり 96 角の升目に余白 4 で収めた下絵で、(n1,n2) はその中の基準点の位置
です。**float で計算します** —— SAMPLE0 の 2 つ目は double なら 43.032702、
float なら 43.032700 で、本物は 43.032700 です。

座標は図面の単位ではなく**実寸のミリ**です:

    ミリ = (単位 − 基準点) × (float)(用紙幅 / 518) × 縮尺の分母

これも掛ける順まで測ってあります。**float で一度に掛ける**のが正解で、
用紙と縮尺を続けて掛けると 1 ulp ずれます（SAMPLE0 の
-9.9427490234375 が c0b66cab と c0b66cac、TEST1 の 124.18013763427734 が
c6c408f0 と c6c408f1。本物は前者）。

記録は図面のものをそのまま写しますが、**2 か所だけ違います**:

* 属性 4 バイトのうち 3 番目（レイヤの次）に **bit 1 が立ちます**。4 種類
  すべてで。SAMPLE0 の線は 00 → 02、TEST1 の文字は 80/08/00/0a →
  82/0a/02/0a、01 のものは 03 になるので「立てている」のであって書き換えて
  いるのではありません。
* **円弧だけ 2 番目が 0 になります**。TEST1 の円弧は 10 → 00、TEST3 の
  円弧は 0d → 00。同じ bit を持つ TEST1 の線（30）は 30 のままなので、
  bit ではなく円弧の話です。

選択が空のときは**ファイルを作りません**（`書き込みます` は出るし ① 実 行
も効くのに、ディレクトリは空のまま。TEST1 の 140,130-320,225 で実測）。

**一覧の画面**（①登録のものと同じ升目）:

* 升目は縦線 x=144+96c（c=0..5）、横線 y=56+32r（r=0..10）。5 列 10 行 = 50。
  HELP の「各々５０個」と合います。
* セルの文字は桁 20+12c、行 5+2r に `" %-9s"`（10 文字）。①登録は先頭が
  ` 新規登録 ` で図形はその次から、②読込は先頭から図形。
* **選ばれているセルだけ黒地白**（bg=0xFFFF）、ほかは白文字。
* `数=` は**セルの数**。空のグループに①登録で入ると 数=1（新規登録だけ）、
  1 つある所に①登録で 数=2、そのグループを②読込で開くと 数=1。4 例で確認。
* 並びは名前順（BOX を先に作って AAA を後から作っても AAA が先）。ただし
  ホストが返す順も名前順なので、この 2 つは区別できていません。
* **別のセルを押すと選択が動くだけ、選ばれているセルを押すと取る。**
  図面一覧と同じ規則で、同じように実測（AAA と BOX があるとき BOX のセルを
  1 回押すと BOX が黒地白・AAA が白文字になるだけ、2 回目で取る）。

**仮表示**（取ってから 1 個目を置くまで）:

* 線・円・点は**色 2 の排他的論理和**。白い枠と重なる画素が 00ffff（7 xor 2）。
* 文字は**箱、色 1** の排他的論理和（黒の上で 0000ff、紫の文字の上で f30000、
  白い線の上で ffff00 —— どれも 1 との排他的論理和）。図面自身は読める字を
  描いている所でも箱です。
* その箱は**図面が小さすぎる字に描く箱とは違う**: 上下の桁を float から
  **切り捨て**（`trunc(y)` と `trunc(y − 高さ)`）、辺は 4 本で、基線の 1 つ上の
  5 本目が無い。
* **1 個置いたら仮表示は消えます。** 押した瞬間も、そのあとポインタを 2 回
  動かしても、2 個目を置いても出ません（⑤仮表示 が戻すのだと思いますが、
  そのセルは未実装）。
* ①選択確定 で取ったときはポインタが上の行にいるので何も出ません。作図範囲
  に入ると出ます。

* レイヤは**図面の書込レイヤ**。図形が持っていたレイヤは捨てます

* 属性の 3 番目は 線と文字が **bit 7 だけ残す**（02・03・0a・4a → 00、
  82 → 80。これが縦書き）、円弧と点は **0x10 になる**。4 番目は 線と文字が

* 置いたものは**上に残ります**（`jw_cmd_after` が描き直す）。図面の字と
  交差する所で 18 画素ぶん違っていました。

#### ｵﾌﾟｼｮﾝ ①建具平面（道は一致、最後の 1 ulp だけ残っている）

    ｵﾌﾟｼｮﾝ → ①建具平面 → 16 個の見本

**同じ行が 2 通りあります。** 見本を押したときの行には `[ESC]` が無く（前の
`建具選択` の行のものが残っているから）、建具を入れたあとの行には有ります。

置き方（`sh tools/tateguplace.sh` が原作に置かせて図面を保存し、レコードを
読めるようにします）:

* 部品は**内法 ÷ (部品数 − 1)** ミリずつ、基準線に沿って並びます。
* **最後の部品**が、押した点を基準線に下ろした所に来ます。手前に戻る向き。
* 記録の y は**基準線を 35 として** `(y − 35) × 見込 ÷ 70` ミリ。見込を 14 に
  すると同じ y=47 が 12mm から 2.4mm になります。ライブラリは 70mm の壁に
  合わせて描いてあります。
* 法線は基準線の向きを**反時計回りに四分の一**。SAMPLE0 の線 1 は +x 向きで
  y=47 が上に、線 0 は +y 向きで y=47 が左に来ます。
* **枠幅は、1 つの部品の中で閉じている記録の x を伸ばします。** 3 番目の
  見本の `2 2 0 0 25 0` は枠幅 35 で 35mm、70 で 70mm になります。部品を
  またぐ記録（1 番目の見本の `1 2 0 47 35 47`）は伸びません。25 を掛け算で
  伸ばしているのか、25 が枠幅に置き換わっているのかは**まだ区別できていま
  せん**（測った記録の x が全部 25 だったため）。
* ミリは図形と同じ `1 / jwc_zukei_scale` で、**割り算**のほう。
* 属性は `00 0e 00 90`（書込レイヤ、それから 0e 00 90）。線種と線色は図面の
  ものと記録のもの。
* 仮表示はポインタに付いてきて、**色 2 の排他的論理和**（白い枠と重なる画素が
  00ffff）。基準線そのものは色 2 でべた塗り。

**残っている差**: 原点が本物より **1 ulp 低い**（押した点 229 に対して本物は
228.9998779 = 4364fff8）。そのせいで仮表示と置いた記録が 1 画素ぶん横に
ずれます —— 1 番目の見本で 1 画素、3 番目の見本のように縦の記録があると
243 画素。`229 - 1800/k` は本物と完全に一致するのに、`229 - 900/k` は 1 ulp
違う、という形なので、部品の位置の出し方がまだ同じではありません。

円弧の記録（`E` が付いたもの）は**まだ置きません**。

### 点のグリッド —— 解けています

14 枚のうち SAMPLE1 だけが点いています。個数の行（2 行目）から:

| フィールド | 中身 |
|---|---|
| 11 | 紙。A-4 が 4、A-3 が 3、A-2 が 2 |
| 25, 26 | 刻み。**紙の上のミリ**。SAMPLE1 は 9,9、ほかは 5,5 |
| 29 | 入切。SAMPLE1 だけ 1 |

ミリから図面単位へは紙で換算します——JW_CAD は紙の幅を作図領域 518 画素に
合わせるので、**1 ミリ ＝ `518 / 紙幅` 単位**。当て推量ではなく、本物の
表示倍率（DGROUP `0x896e` の倍精度）が A-4 の 2 枚で 0.5723906、A-3 の
3 枚で 0.4047689、A-2 の 1 枚で 0.2862 —— 比が 1 : 1/√2 : 1/2 で紙そのもの、
という測定から来ています。図面の中にも同じ係数が出ていて、n 文字ぶんの
「幅＋間隔」ミリが `n*(幅+間隔)*518/紙幅` 単位を占めます（TEST7 も、
自分の 678 を戻せば同じ）。

SAMPLE1 で答え合わせすると 9 ミリ＝15.69697 単位、点は
`121 + k*15.69697` の切り捨てで 136 152 168 183 199 215 230 … 623。
33 列 29 行ぜんぶ合い、ずれはありません（グリッドは図面の原点を通る）。

### 字を縮めるやりかた —— 解けています

**本物は図面の文字を「行ごとの横線」として描きます。** 字形を転送する
`20a9:014e` はメニュー専用で図面には一度も来ないし、点を 1 つずつ打っても
いません。1 行ぶんのドットを**線種のパターン**にした横線を、字の高さのぶんだけ
引きます。9 画素の字なら 9 画素の線が 9 本。

見つけかたは、見出しの下の画面バイトを**どの命令が書くか**を見るだけです。

```sh
cd ../dosv_emu_cpp
# 画面の y=245, x=378 あたりのバイト = A000:(245*80 + 378/8)
DOSEMU_WATCH=A4CBF-A4CC2 ./dosemu ... TEST6.JWC        # -> 20a9:094b（線ルーチン）
DOSEMU_BP=+10A9:07DC     ./dosemu ... TEST6.JWC         # -> 横線＋パターン
```

そのパターンがそのまま「縮んだ行」なので、39 個集めて 16 列から 9 列への
単調写像を全部試すと、39 個ぜんぶを再現する組はただ 1 つ:

    dst_x = floor(src_x * h / 16)
    dst_y = floor(y0 + src_y * h / 16)

`h` は字の高さの**小数のままの値**——TEST6 の見出しでは 9 ではなく 8.690。
`y0` は枠の上端で、これも小数（基準線 − h）。行と列で別々に切り捨てるので
行の写像と列の写像が違うものになります。整数だけの規則がどれも合わなかった
理由がこれで、違いは `y0` の小数部が全部でした。

### 円弧 —— 解けています（`src/draw.c` は 1def:0228 の写し）

**角度は「度＋1万分の1の端数」ではなく 32 ビットの 16.16 固定小数です。**
`.JWC` の円弧レコードの `+14` と `+18` が `long`。SAMPLE6 の傾いた楕円は
開始角に `0x00a247f8` = 162.2655 を持っていて、本物が円弧ルーチンに渡す
long と 1 ビットも違いません。度と端数として読むと 160.158 になり、
1.5 度ずれて折れ線の頂点が全部動きます。

本物の生成ルーチンは `1def:0228`。引数はこう読みます:

```sh
DOSEMU_BP=+0DEF:0228 DOSEMU_BPN=24 DOSEMU_BPDBL=2,6,10 ../dosv_emu_cpp/dosemu.exe ...
```

| 語 | |
|---|---|
| 2..5 | `double cx` —— **画面座標**。呼ぶ側が変換済み |
| 6..9 | `double cy` |
| 10..13 | `double r` —— 切り捨て前の半径 |
| 14..15 | `long` 開始角（16.16） |
| 16..17 | `long` 終了角（16.16） |
| 18 | 色 |
| 19 | 線種のパターン |
| 20 | `flatten`（×10000） |
| 21..22 | `long` 傾き（16.16） |

中身は:

* `rx = (long)r`、`ry = (long)(flatten * r * 0.0001)`
* 刻みは `rx` が 20 未満で 20 度、80/160/320/640 で 10/8/5/2/1 度
* 頂点は **開始角そのまま → `floor(開始角) + 刻み` から整数度で終端まで →
  終了角そのまま**。端数を落とすのは本物がそうしていて（低位語に 0 を書く）、
  だから途中の頂点はぜんぶ整数三角関数の表から出ます
* 終端は `終了角 > 開始角` でなければ 360 度足したもの

整数三角関数は `1000:0965`（cos）と `1000:083a`（sin）。**リンク時の番地なので
エミュレータでは `1110:0965`** です（`0EFF:2A75` としても出ます）。表は DGROUP
`0x1b44..0x1cac` の `round(cos(度) * 65536)` を 91 本、前から読めば sin、
後ろから読めば cos、90 度と 180 度を越えたら符号を変える。端数のある角度だけ
浮動小数の `cos`/`sin` に落ち、度→ラジアンの定数は DGROUP `0x91e0`
（ちょうど `pi/180/65536`）。

**丸めが当てられない部分です。** 積を**ゼロから遠い側に**半単位ずらして
floor する（`prod > 0 ? prod+0x8000 : prod-0x8000` してから高位語を取る）。
だから `値(r, 180)` は `-r` ではなく `-r-1`、`値(r, 90)` は 0 ではなく -1。
折れ線が左と下で真円の内側に 1 画素寄るのはこれです。

傾きは 16.16 の cos/sin で回します:

```
x = cx + ((u*ct) >> 16) + ((v*st) >> 16)      u = cos16(rx, 角)
y = cy + ((v*ct) >> 16) - ((u*st) >> 16)      v = -sin16(ry, 角)
```

**`ct`/`st` は本物から読むしかありません**（`DOSEMU_BP=+0DEF:061E,+0DEF:0667`）。
0 度 → (65536, 0)、**90 度 → (0, 65535)**、180 度 → (-65536, 0)、
270 度 → (0, -65536)。90 度の sin だけ 1 に届かないので 65535 です。
65536 にすると、傾き 90 度の円弧が丸ごと 1 画素横にずれます。

**画素で打つのは `flatten == 10000` かつ `(long)r < 10` かつ作図領域に
丸ごと収まるときだけ**（画素ルーチンは切り取りをしない）。そのとき傾きは
角度に足し込まれて渡され（`start + tilt`、`end + tilt`）、`flatten` は
渡りません——ただの円です。楕円は大きさに関係なく折れ線。

小さい円の画素は中点楕円法で、領域の境目は教科書の
`a²(y-0.5) > b²(x+1)` ではなく**素の `a²y > b²x`**。半径 1 だけ別扱いで
`(0,1)(1,1)(1,0)`。半径 2〜9 は素の式で 1 点も違いません。

**掃引は角度では渡っていません。**`FUN_20a9_0d1a`（リンク `10a9:0d1a`）は
最大五つの「破片」の表を受け取ります——破片ひとつが**象限ひとつと画面座標の
箱ひとつ**で、歩きが出す点を象限へ折り返して、その箱の中にあるものだけを
描く:

```
cmp [bx+si+0x32], ax   jge ...    x <= 箱.xhi
cmp [bx+si+0x3c], ax   jle ...    x >= 箱.xlo
cmp [bx+si+0x46], ax   jl  ...    y <= 箱.yhi
cmp [bx+si+0x50], ax   jg  ...    y >= 箱.ylo
```

象限は `[bx+si+0x28]`、`-1` で表の終わり。箱は軸に平行な長方形なので
角度そのものとは違い、**終端角を少し過ぎた点でも箱の中なら描かれます**。
どんな角度判定でも作れない振る舞いで、ここを合わせようとして何度も外して
いました。表は本物から読めます:

```sh
DOSEMU_BP=+10A9:0D1A DOSEMU_BPPTR=8 DOSEMU_BPPTRAT=40 DOSEMU_BPPTRN=50
```

中心 (150,120)、半径 5、0..22 度の円弧ひとつで `象限 0 / x 154..155 /
y 118..120`。中心を (150.5,120.25)、半径を 5.6 にしても同じ数字が出るので、
**箱は切り捨てた中心と半径から**作られています——154 は
`(int)(150 + 5*cos 22)`、118 は `(int)(120 - 5*sin 22)` で、**切り捨ては
中心を足した後**。掃引は象限の境目で切られ、各破片の箱はその破片の両端が
作ります。`tools/qarc.py` が掃引を並べて聞く道具です（半径 1〜9、傾きと
端数半径つきの無作為 180 通りで 1 点も違いません）。

**傾きも 16.16 の long です。** レコードの `+22` から 4 バイト。SAMPLE2 には
`0x0059ffeb` = 88.99968 度で傾いた楕円が四つあり、上位ワードだけ読んで 89 度
にすると、その連鎖の頂点がひとつずつずれます。

折れ線のループは `角度 < 終端` で回します（`<=` ではなく）。掃引の終わりが
ちょうど刻みの上に来ると、その頂点を二度出してしまい、余分な長さ 0 の断片が
点をひとつ置いて破線のパターンも一つ進めるからです。本物が全円に対して出す
連鎖は 46 本で、`<=` では 47 本になります。

### 3. 本物の UI —— 解けています（`src/ui.c`）

**図面なしの起動画面も、図面を読み込んだ画面 13 枚も、640x480 が
まるごと 0 画素差です**（`sh tools/ui.sh`、`sh tools/full.sh`）。

読みかたは全部同じ——本物が呼んでいるものを読む:

    DOSEMU_BP=+10A9:07DC                   線 20a9:07dc
    DOSEMU_BP=+0DEF:23C5 DOSEMU_BPSTR=2    文字列 1def:23c5
    DOSEMU_BP=+0DEF:1691                   全角字形を 1 画素ずつ置くルーチン
    DOSEMU_BP=+10A9:0AC5                   楕円（レイヤ釦の丸）
    DOSEMU_BP=+0DEF:1460                   矩形塗り
    DOSEMU_BP=+0DEF:075C                   1 画素

分かったことを並べておきます。

**1def:1691 —— 全角字形を歩いて 1 画素ずつ置く。** メニューの文字とは
別の道です。刻みは DGROUP の 4 バイト浮動小数で、0x9224 が 1.0（本物の
漢字）、0x9228 が 0.5。符号が 400 未満なら上位バイトに 0x22 を足して
全角英数にします（0x0130 -> JIS 0x2330 = '０'）。行 r 列 c の点は
`(int)(x + 刻み*c), (int)(y + 刻み*r)`。レイヤ釦の数字も白帯の "ALL" も
下帯の 電卓 と Home もこれです。1,340 個の画素呼び出しと完全一致。

**文字列ルーチンの最後の引数は色ではありません。** 0 は背景を黒で塗る、
2 は触らない、1 か -1 は行の矩形を fg で塗ってから文字を**黒で透過**で
書く（0def:24a6 が色を両方 0 にする）。下帯の 範囲記憶 が緑の釦に黒で
乗るのはこれ。

**パネルの数字は図面の 1 行目から。** 11 番=用紙、12 番=ペン、13 番=線種、
9 番=縮尺、10 番=書込レイヤ、18 番=作業時間（秒）。本物が DGROUP の
0x0a68 / 0x0a6a / 0x0a6c / 0x0b26 / 0xc134 に持っている値と 14 枚とも
一致します。用紙名は 0885:100d、縮尺の文字列は 0885:1079 のとおり
（1 未満は逆向き、4.9 未満は小数点つき。SAMPLE0 が `S=1/1.0`）。
`Pen.n` の色はペン色表（DGROUP 0x0a70）で、線種が 9 以上なら
`Addi.L` / `Rnd.fn` / `Long.L`（TEST7）。表示倍率は 170mm ÷ 用紙の幅。

**レイヤ釦。** 上の 2 本の短い帯は、左が「線・円弧・点のどれかがある」、
右が「文字がある」（色 3）。丸は 2 枚あるレイヤ表の**1 枚目**が立って
いるときだけ（TEST7 の C D E は 1 枚目が 0 で数字だけ）。非表示の
レイヤは数字も丸も描きません（SAMPLE0 のレイヤ 1）。レイヤ名は
点レコードの直後に 8 バイト x 256 個並んでいて、パネルは書込レイヤの
ものを出します。

**メニューの仕切りの中の細い棒は作業時間です。** 本物は起動時に
セッション時計を `time() - 18番` に合わせるので、DGROUP 0xc134 の long に
18 番を足すと 14 枚とも同じ定数になります（エミュレータの固定時計）。
秒を `q = 秒 * 16 / 3600` に直して、`q % 160` を下から色 5 で、
`q / 10`（上限 240）を上から色 6 で塗ります。

**マウスの矢印は 0885:4f03。** 三角 11 行と 3 画素の尾 5 段を、
プレーン 1 と 2 に排他的論理和（GC の 3 番に 0x18）で置きます。だから
もう一度描くと画面が元に戻る。矢印の下端は DS:0a60（463）より下に
行かないように引き上げられます。

### 4. 点線はほぼ合っている

長い破線を 1 本選んで両方の画素を並べたら、水平線は**完全に一致**、

### 4.7 読取 —— 右ボタンが拾う点（`src/read.c`）

本物の上の行はどの作図命令でも `(L)free (R)Read` と言います。右ボタンは
**読取**——近くの決まった点に吸い付く——で、同梱の `orig/JW_CADV.HLP`

    目盛、点、線･円･楕円の端点と交点、文字の左下・右下点位置
　　の読取り（スナップ）をします。

6)読取り範囲内（約８ﾄﾞｯﾄ）にある読取り点に対する優先順位は
　　（優先順位高）目盛 → 仮点 → 実点 → 端点・交点 →

書いてあることは全部、動いている本物で測り直しました（`tools/read.sh`。

拾いません。`start == end` の弧は飛ばしています。

まだ入れていないもの: 修飾キーの読取（[SHIFT] 線上の点、[GRPH] 中心点、
[CTRL] 鉛直・円周1/4点——帯の 17 桁目と 22 桁目が言っているのはこれ）、

`mods shift` / `mods ctrl` / `mods alt`、離すのは `mods none`。
（2026-09-18 まで `INT 16h AH=12h` に答えていなかったので、本物はずっと
Ctrl を押されていると思っていました。「刺された罠」を先に読むこと。）

**本物は読取を取りこぼすことがあります。** 1 回の起動で右ボタンを続けて
押すと、拾えるはずのところで「読取可能データ無」と言う押しが混ざります。
押す間隔を変えると*どの押しが外れるかが動く*ので（SAMPLE6 で押したあとの
待ちを 14M → 60M 命令にすると当たり外れが入れ替わる）、本物の中の競合で、
移植すべき規則ではないと見ています。起動しなおして 1 回だけ押せば必ず
拾えるので、`tools/readcheck.sh` は 1 点につき 1 回起動します。

**点は仮点を落とします。** 押したところに、指定点と同じ形の
**半径 2 の白い輪 12 画素**が出ます。SAMPLE0 で (300,250) を押して測りました:

* 本数はどちらも変わりません（30|13 のまま）。図面の実体ではない
* 別の項目を選んでも残ります。押すたびに増えます
* **100 個まで**。130 回押すと輪は 100 個（最初の 100 個）で、101 回目から
  あとは何も描かれません。古いものを捨てる輪ではないし、何も言いません
  （上の行も帯も 100 回目のあとと同じ）
* 押したあとに本物は **[ESC]・と上の行をもう一度**書きます。項目を選んだ
  だけでは [ESC] は出ません——最初の押しで出ます（`src/stage.h` の 22 番）

保存されるものかどうかは、まだ書き出しを作っていないので測れていません。
移植は `Jwc` に `n_temp` / `temp_x` / `temp_y` で持ち、画面には**いちばん
最後**（格子より後）に描きます——本物が押した瞬間に上から描いているので、
突き合わせられる画面はどれもそうなっています。

**線消は円弧も消します。** 本物の上の行が
「線,円弧をマウス指示」と言うとおりです。SAMPLE6 の 19〜24 番の円弧
（半径 27.9 の四分円）で測りました:

* 拾える範囲は線と同じ **8**。弧から 7.8 のところ（画面 (245,141)）は
  消えて、8.53 のところ（(244,140)）は何も起きない
* **描いていない部分は拾いません**。19 番の円の残り四分の三のうち
  (254,120) は円から 0.28、(255,118) は 0.31 ——どちらも無反応。
  `start`〜`end`（`end` が `start` を越えていなければ 1 周足す）に
  `tilt` を戻して当てはめます（`jw_arc_poly` と同じ角度の取りかた）
* **線が先です**。(283,236) は 21 番の弧のちょうど上で線からは 2.19、
  (351,179) は 20 番の弧の上で線からは 0.06 ——どちらも減るのは線数

楕円（`flatten` が 10000 でないもの）は、同梱の 14 枚に「まわりから
離れていて測れるもの」が無いので手を付けていません。

**何も無いところを押すと本物は「読取可能データ無」と言います。**
本数の隣、32 桁目・2 行目に色 7 で。左右どちらのボタンでも同じです。
出たあとは、**次の押しで何か拾えるか、別の項目を選ぶまで**消えません
（SAMPLE6 で (244,140) → (446,189) と押すと消え、(244,140) のあと
複写を選んでも消える——どちらも測りました）。

文字列の先頭は **BEL (0x07)** で、1 桁ぶん進みますが何も描きません。
本物はその文字を FEP に問い合わせもしません（`DOSEMU_FONT_TRACE=1` で
コード 0007 の要求が 1 度も出ない）。JWANK16.FNT には小さな輪の字形が
入っているので、素直に描くと本物と 12 画素違います。`src/ui.c` の
`jw_ui_text` は 0x20 未満を「1 桁進めて何も描かない」にしています。
エミュレータのログは 0x20 未満を全部 `.` で出すので、ログの
`".読取可能データ無"` の先頭は句点ではありません（`DOSEMU_BPPTR` で
ポインタの先の 4 バイトを見ると `07 93 C7 8E`）。

**引いている途中も本物と同じです。** 1 点押したあとマウスを動かすと、
本物は取った点からポインタまで**色 2 の線を排他的論理和で**引きます
（□ は矩形 4 本、○ は円）。帯の 長／角度 も動かすたびに書き換わります。
`src/cmd.c` の `jw_cmd_band()` と `jw_cmd_track()`、検査は
`sh tools/bandcheck.sh 3 300 200 450 320`。残るのは丸数字だけです。

**押したあとの上の行と帯も出します。** `src/stage.h` が
`tools/stage_table.py` の生成物で、本物が各段で書いた文字を、書いた時刻で
段に分けて持っています。描きかたも本物どおり——段が進むたびに
**上の行を黒で塗り（(0,0)-(639,15)）、本数の箱を色 4 で塗り直して**から
その段の文字を書きます。塗り直しが要るのは、どちらも透過で書くので
重ねると両方読めてしまうからです。

長さは紙のミリ（図面単位 ÷ `unit_mm` × 縮尺）、角度は度。

残っている食い違いは 3 つ:

* 本物は新しい線を画面に**上から**描きます。移植は図面をファイルの順に
  描き直すので、新しい線が文字や円と重なるところだけ色が違います
  （SAMPLE6 の矩形で 15 画素、SAMPLE3 の円で 1 画素）
* TEST7 に線を 1 本足すと差が大きく増えます。もともとある 64KB の
  バグ（下の「TEST7 の 101 画素」）がレコードの増減で動くからです

**小数の桁数は解けました。** 縮尺から出ます —— 本物の縮尺を
`tools/askword.py` で 1 から 1000 まで振ると、1/10 までが 3 桁、
1/20 から 1/100 が 2 桁、1/150 から上が 1 桁。つまり「3 から始めて、
縮尺が 10 を越えるたびに 1 減らす」。角度はいつも 3 桁です（度なので
縮尺は関係ない）。

**縮尺そのものは 1 行目の 9 番から読んでいますが、本物はそこを
読んでいません。** `tools/asktext.py` で 9 番を書き換えても画面は
変わらず、メモリ像のほう（14 枚中 13 枚は 0x705 の語、SAMPLE2 だけ
そこが float）が効きます。本物は保存するときに 9 番へ書き写すので、
同梱の 14 枚では必ず一致します —— なので移植は 9 番を読んでいます。
`tools/askword.py` で作った図面だけは食い違います。

**押したあとに本物が出す文字はまだです。** 読んだものは書いておきます:

| いつ | 出るもの |
|---|---|
| ／ を選んだ直後 | 上の行 `◇始点指示 (L)free (R)Read |①  ＋  |②寸 法 |③角 度 |④平 行 |⑤垂 直 |`。帯の 17 桁目の `鉛直･` と 22 桁目の `円周点`（読取の種類）は **[CTRL] を押しているときだけ** |
| 1 点目を押したあと | 上の行が `[ESC]・◆終点指示 …` に |
| 2 点目を押したとき | 帯に `長=   57.336` と `角度=   0.000ﾟ` |
| 線が増えたあと | 本数が 30 から 31 に。上の行が `[ESC]` `・` `始点指示 (L)free (R)Read 確定長さ =   57.336(mm)角度=   0.000ﾟ` `[BS]前項` |

**長さは紙のミリです。** (300,200) から (400,200) —— 100 画素 —— で
57.336 mm。100/57.336 = 1.74411 = 518/297、つまり `unit_mm` です
（A-4 の SAMPLE0、S=1/1）。角度は図面座標の atan2 を度で。

### 4.11 ①〜⑨ —— 本物は字形を描いていません

上の行は `|①実行(L)|②中止(R)|` のような丸数字だらけで、これが長いこと
「フォントに無いから両方あきらめる字」として残っていました。**違いました。**

`DOSEMU_FONT_TRACE=1` で本物が字形を頼む符号を並べると、①が出るはずの
ところで頼んでいるのは `8 0031`（半角の '1'）と `8 0029`（半角の ')'）です。
本物のコードは `0x1046d`:

```asm
    cmp  word ptr [bp-0eh], 8740h   ; ① より下なら普通の漢字
    jb   normal
    cmp  word ptr [bp-0eh], 8748h   ; ⑨ より上なら普通の漢字
    ja   normal
    test byte ptr [129h], 1         ; この機械の字形に 13 区があるか
    jne  normal
    mov  ax, word ptr [bp-0eh]
    add  ax, 78f1h                  ; 8740h + 78f1h = 1 0031h -> '1'
    push ax  ... call 10a9:03e1     ; 桁 col に digit
    mov  ax, 29h                    ; ')'
    push ax  ... call 10a9:03e1     ; 桁 col+1 に ')'
```

NEC 選定 IBM 拡張の 13 区は JIS X 0208 に無く、DOS/V の字形にも入って
いません。だから本物は**全角 1 文字ぶんの枠を半角 2 つに割って
「1)」「2)」…と書きます**。`8740h`〜`8748h` すなわち ①〜⑨ だけで、
⑩ から先はこの枝に入りません（`10)` は 3 桁で枠に入らないからでしょう）。

DGROUP `0129h` のビット0 が立っていると普通の漢字として描きます——
13 区を持っている機械、つまり PC-98 のことです。DOS/V では 0 でした
（`dump +3375:0129` で読めます）。

移植の `jw_ui_text()` に同じ枝を入れて、
`tools/menucheck.sh` が 269 → 2 画素、`tools/pressfull.sh 25 …` が
67 → 0 画素になりました。

**残る 2 画素**は複写（1 番）と移動（16 番）の `(0,16)` が 1 画素ずつで、
**本物のほうが黒**です。これは**本物の側のバグ**でした。

`DOSEMU_BP=+10a9:07dc`（線ルーチン）で最後の呼び出しを読むと:

```
44172552  (640,15)-(639,15) col=0 rop=0 style=FFFF
```

**x0 が x1 より右**、つまり幅ゼロの走査線です。上の行に書いた文字列の
右側を消すのに、本物は 0〜15 行それぞれで「書いた桁の次から 639 まで」を
黒く塗りますが、文字列がちょうど 80 桁目まで届いていると始まりが 640 に
なります。線ルーチンはバイト番号を `x0>>3`=80、`x1>>3`=79 と出し、
始まりが終わりより後ろなので端数バイトを 1 つだけ書く枝（`10a9:094b`）に
入り、**行の終わりの次のバイト＝次の行の先頭**をマスクつきで塗ります。
15 行目の次は 16 行目——白い区切り線の左端です。

移植でこれを出すには、(1) 上の行の右側を消す段と (2) `x0>x1` のときの
線ルーチンの挙動の両方を写さなければなりません。どちらも移植には無く、
**当てはめで 1 画素を合わせにいかないこと**。TEST7 の 95 画素と同じ扱いに
してあります。

**2026-09-18 に出る場所が増えました。** エミュレータの幻の Ctrl を直したら、

#### 4.48c 測るのを速くしました（1 件 10 秒 → 一覧 64 通りで 1 秒）

利用者から「計測が遅すぎない？」（2026-09-26）。測ってみたら、1 件 10 秒の
うち **6 秒が DOS の起動**で、残りも半分は子プロセスを起こす代金でした。

**効いた順に 3 つ**:

1. **本物の絵を取っておく**（`tmp/origcache`）。同じ EXE に同じ手順なら
   必ず同じ絵なので、2 度目からは起動ごと省けます。**移植を直して測り直す
   ときが速い**——それがいちばん多いやり方です。EXE・フォント・`orig/` の
   `ls -l` を鍵に混ぜてあり、どれかが変わったら全部捨てます
   （**古い絵と比べるのがいちばん危ない**）。
2. **移植側を node 1 つにまとめる**（`tools/seqall.mjs`）。1 件ごとに node と
   python を起こすと、測りより起動のほうが高くつきます（Git Bash では
   子プロセス 1 つが 50ms 近い）。64 通りで **1.2 秒**になりました。
3. **並べて走らせる**（`tools/runcases.sh`、既定 6 本）。本物をまだ撮って
   いない件だけに効きます。8 コアで 6 本、3.6 倍。

    | | 64 通り |
    |---|---|
    | 前（1 件ずつ） | **11 分** |
    | 並列だけ | 3 分 |
    | 絵を取っておいて node 1 つ | **1.2 秒** |

**使い方**——手順は `tools/cases/*.txt` に 1 行 1 件（名前と手順はタブ、
手順どうしは `|`）。名前が `~` で始まる行は「分かっている残り」で、数に
入れません。

    sh tools/cases.sh tools/cases/calc.txt        # ぜんぶ
    sh tools/cases.sh tools/cases/calc.txt f2     # 名前で絞る
    sh tools/calccheck.sh                         # 同じ（電卓）
    sh tools/stripcheck.sh                        # 同じ（下の帯）

新しい件を足したら、本物をまだ撮っていないので 1 回だけ遅くなります
（6 秒 x 件数 ÷ 6 本）。そのあとは 1 秒です。

**踏んだもの 2 つ**:

* **客の作業場を `%TEMP%` に置くと 25 倍遅くなります**（1 件 10 秒が 2 分

* `seqcheck.sh` の中で `basename` や `awk` を呼ばないこと。62 個 x 6 本で

`tools/check.sh` は図面と命令を端から端まで通す大きいほうで、**commit の

盤は ｸﾞﾙｰﾌﾟモードのまま（赤い字と 16 升）で、ペンの行・紙の行・

### 4.36 紙 と 縮尺 —— **打ち込みの欄でした**（`src/main_wasm.c`、`src/ui.c`）

左の盤の 紙（x 1〜47、y 321〜335）と、その右の 縮尺（x 48〜120）。
どちらも押すと上の行に質問が出て、**数字を打って [Enter]** です。

| 押すところ | 上の行 | 欄 |
|---|---|---|
| 紙 | `[ESC]  ` ＋ 桁 18 `用紙 サイズ (A0～A4） 変更` ＋ 桁 46 `A-` | 桁 48 |
| 縮尺 | `[ESC]  ` ＋ 桁 18 `レイヤ グループ縮尺 変更` ＋ 桁 45 `倍率=` | 桁 50 |

**押した直後の画面は本物と 0 画素差**です（`sh tools/clickcheck.sh`）。

**そこに行くまでに 3 回外しました。** 押しても何も起きない → もう一度
押しても変わらない（周回ではない）→ 数字キーだけでも変わらない。
決め手は `A-` の右にある**緑の升**でした——ほかの数値欄と同じ
カーソルで、つまり「打って [Enter]」。SAMPLE0 で `2`＋[Enter] を送ると
A-4 → A-2、縮尺なら S=1/1.0 → S=1/2.0 になります。

**数字を入れたあとも合いました。** 紙を A-4 から A-2 にすると
**本物の図面は半分になります**——`unit_mm = 518 / 紙の幅` なので、
紙が倍になれば絵は半分。作図範囲の点灯画素が 2421 → 1212 です。

**縮むのは view ではなく図形の座標でした。** 最初 `view.scale` に比を
掛けて、絵はぴったり重なったのに**赤い用紙枠が 239 画素出てしまう**——
用紙枠は図面座標の (0,0)-(518,447) なので、倍率 1 のときだけ画面の右外に
隠れているからです。本物の DGROUP を読んで決着しました:

| | 紙の前 | 紙のあと |
|---|---|---|
| `0x0c30`（描画倍率) | 1.0 | **1.0**（動かない） |
| `0x896e`（帯の表示倍率） | 0.5723906 | 0.2861953（ちょうど半分） |

倍率は動いていません。帯の `表示倍率` は **170 ÷ 紙の幅**（170/297 =
0.5724、170/594 = 0.2862）で、紙だけで決まる数です。つまり本物は
**図面をミリで持っていて、`518 / 紙幅` でその場で単位に直している**——
`jwc_set_paper` が線・円・文字・点・グリッドの座標に比を掛けます。

`sh tools/papercheck.sh`（`N=0`〜`N=4`）で、**作図範囲は 4 枚とも 0 画素差**。

**[Enter] のあと本物は 入出力（30 番）を選んだ状態になります。**
メニューの升が反転して、上の行が
`|①ファイル(L)|②プロッタ(R)|③プリンタ|④自動保存(無)|⑤新規図面|⑥終了|`
に変わります。この行は `src/prompt.h` に前からあったので、
`ui.command = 30` を立てるだけで **A-0〜A-4 の 5 枚とも画面全体 0 画素差**
になりました。

**帯を消さない場合があります。** メニューを選ぶと上の行の下の 2 行
（y 17〜47）が黒くなりますが、紙と縮尺は**そのあと図面を描き直す**ので
帯は図面で埋まります。`JwUi.band_kept` がその区別です。

### 5. マウスとキー —— ここが次

`INT 33h` が root に 7、ovl08 に 7。カーソルはソフトで描いています
（描きかたは上の「本物の UI」）。

**修飾キーも流し込めます** —— 台本の `mods shift` / `mods ctrl` /
`mods alt`（`grph` も同じ）、離すのは `mods none`。押し下げっぱなしの状態を

追加･除外 の「書込みのペン・線種だけ」も、ここから測れます。

**次にやること。** エミュレータは台本でマウスとキーを動かせます:

```sh
printf 'wait 40000000\nmouse 90 70\nwait 2000000\nclick left\nwait 20000000\nshot ../jwcad_dos_wasm/tmp/m1.raw\n' > tmp/m.txt
../dosv_emu_cpp/dosemu.exe --root orig --font-ank font/JWANK16.FNT \
    --font-kanji font/JWKAN16.FNT --script tmp/m.txt orig/JW_CADV.EXE SAMPLE2.JWC
```

これで 複写 を押すと、メニューが**その下位メニューに入れ替わり**、
選んだ行が反転し、案内文と題名帯も変わります。つまり「押したあとの画面」も
`tools/full.sh` と同じやりかたで 1 画素まで突き合わせられます。順番は

1. 押した行の反転と下位メニューの文字（文字列呼び出しをそのまま読む）
2. 案内文と題名帯
3. コマンドの中身

`src/ui.c` に `jw_ui_menu_hit()` があり、ブラウザ側は
`jw_menu_at()` / `jw_menu_label()` で名前を出すところまで来ています。

### 「%PDF で始まって %%EOF で終わる」は PDF の検査ではない

`tools/plotcheck.mjs` は PDF の先頭 8 バイトと末尾だけ、PNG は署名と
IEND だけを見ていました。**この検査は壊れたファイルを通します**——
`src/png.c` の deflate が同じデータを 2 度出していたときのファイルは、
署名も IEND も正しく、それでいてどのビューアも開けませんでした。

いまは書き出して**読み直します**。`tools/pdfread.mjs` はビューアと同じに
`startxref` から相互参照表を辿り、各行が本当にそのオブジェクトを指すか、
`/Length` が実長ちょうどか、`/Root` からページに届くか、文字が使う
フォントがページの資源にあるかを見ます。`tools/pngread.mjs` は全チャンクの
CRC を検算し、**node の zlib で**（こちらの deflate ではなく）展開して、
行フィルタを戻し、背景でない画素を数えます。どちらも自前の書き手を
いっさい知りません。


### ｵﾌﾟｼｮﾝ → ①建具平面（途中まで。測った数字はここにある）

上段の行と一覧の枠は本物と一致しています（23,342 → 19,173 画素）。
残りは**16 個の建具の絵**です。

データの形式は**同梱の `JW_OPT1.DAT` 自身の 240 行目以降**に書いてあります
——ブロック数と建具名、`999` 区切り、部材ごとに
`始点ブロック 終点ブロック x1 y1 x2 y2`（＋線色・線種・レイヤ）。
Ｙ（見込）は 70mm 基準、Ｘは 25mm 基準で、左ブロックでは −20mm 以下の端点、
右ブロックでは 20mm 以上の端点が指定寸法へ伸縮、ほかは据え置き。

**ただし文書どおりに書くと合いません。** 本物が実際に引いた線を
`tools/tateguroad.sh` で記録して測った数字:

```
一覧の枠   左の列 x122..380、右の列 x380..638、行は 48 画素おき
           行の下に白い横線（x122..638）、列の間に白い縦線（x380）
建具 [1]  3 ブロック   引かれた線
  1 2 0 47 35 47   -> (150,42)-(258,42)
  2 2 0 -20 0 90   -> (250,59)-(250,31)
  2 3 -35 23 0 23  -> (241,48)-(350,48)
建具 [2]  4 ブロック
  1 2 0 47 35 47   -> (420,42)-(495,42)
  2 2 0 -20 0 90   -> (486,59)-(486,31)
  2 3 -35 23 35 23 -> (477,48)-(562,48)
  3 3 0 -20 0 90   -> (553,59)-(553,31)
  3 4 -35 47 0 47  -> (544,42)-(620,42)
建具 [3]  2 ブロック（行 2、左の列）
  1 1 0 0 -25 0    -> (150,102)-(143,102)
  1 1 0 70 -25 70  -> (150,84)-(143,84)
  1 1 0 0 0 70     -> (150,102)-(150,84)
  1 2 0 35 0 35    -> (150,93)-(350,93)
```

ここから確かに言えること:

* **ブロックは升の中で等間隔**。左の列は x150 から x350、右の列は x420 から
  x620 で、どちらも 200 画素を (ブロック数 − 1) で割る。3 ブロックなら
  150/250/350、4 ブロックなら 420/486.67/553.33/620。**原点は小数のまま持ち、
  画素にするのは最後**（-35 の端が 477 と 562 の両方になるのはこのため）
* Ｙは上向きが増える向きで、行 1 の `y=0` は画素 53.9、行 2 は 101.9。
  行の間隔 48 画素とちょうど合う
* 建具 [3] は Ｙ 70mm が 18 画素（0.257 px/mm）、Ｘ 25mm が 7 画素
  （0.28 px/mm）。**縦と横で倍率が違う**か、Ｘに伸縮が掛かっている

**次にやること**: ①見込 と ②枠幅 を変えて同じ建具を撮り、Ｘ と Ｙ の規則を
分けて確かめる。いまの数字だけでは「Ｘは伸縮していないのか、25→35 で
伸びているのか」が決まりません。当てはめで埋めないこと。
