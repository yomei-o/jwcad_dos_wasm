# 複線 の「範囲外でも段3へ行くが線を足さない」—— decomp 調査（結論：明示の範囲検査は見つからず）

調査日 2026-10-21。読み取り専用（emulator 未使用）。番地はすべて ovl7 の dis 絶対番地（`python tools/altlift.py --ovl 7 ADDR LEN`、
`tools/disasm.py --ovl 7`）。ovl 内の near 番地 = `0x2ab80 + 2ab8:offset`。DGROUP の定数は `JW_CADV.unp.exe` の 32 バイトヘッダを除いた
イメージの `0x3375*16 + DS:off` から直読み。【確】＝命令列から確定、【推】＝推定、【未】＝読めていない。

## 1. 結論（先に）

1. **複線本体（ovl7 `0x2bdb8`〜`0x2e588`）には、新しい線の座標に対する範囲検査は無い**【確】。線の複写は
   `0x2e203`〜`0x2e3d3` で「基準線上の足 u、横ずれ v=gap」から 4 座標を `1bb4:2981/2a18`（ただの座標変換、クランプ無し）で作り、
   そのまま `11f2:67fa(rec)` に渡す。`0x2dd1a`〜`0x2e3d3` の区間に座標の `compare` は 1 つも無い（gap の符号判定 `[0x9798]=0.0` だけ）。
2. **共有の線追加ルーチンにも座標の範囲検査は無い**【確】。`11f2:67fa`（root 0x1871a）→ `11f2:66b3`（root 0x185d3、引数 mode=0）が断るのは次の 2 つだけ：
   * ペン `rec+0x11 < 0x5a` で `x0==x1 && y0==y1`（長さ 0、0x185ef〜0x18625）→ 戻り値 0（線は足されない）。
   * 件数が容量 `[0x13c:0x13e]` を超え、`OVERLAY 28 → 2ab8:43b1`（ovl28 dis 0x2ef31、記憶領域の拡張）が非 0 を返したとき（0x18647〜0x186b9）。
     mode=0 なら `[0x148]--`、全面描き直し `885:23aa`、`0x145f3(DS:0x62c "これ以上描けません")`、そのあと **0x186ba へ落ちて「いまの最後の線」の枠に新しい記録を書き込み 1 を返す**
     （＝新しい線は足されず、**直前の最後の線が上書きされる**ように読める【推】。落ち先が本当にそうなるかは未確認）。
     `43b1` は件数・プール残量しか見ない（座標は引数に無い）【確】。
3. **段3へ行くのに線が無い、という実機の症状は、67fa の戻り値を複線が見ていないことと整合する**【確】：
   `0x2e3d3 lcall 11f2:67fa` の直後（`0x2e3d8 add sp,0x16`）に `ax` の検査が無く、続けて `0x2e3fa mov [bp-0xdc],1`（足した本数＝1）を
   無条件に書く。[ESC]（段3、`0x2c8a3` 側：`[bp-0xdc]>0` なら `0x2c836 11f2:6859([0x148])` で**末尾の線を消す**）は足せたかどうかを知らないので、
   足せていなければ「直前の最後の線」が消える。これが観測（previous last line が消える）の機構【確】。
   → ポートは `jwc_add_line` が 1 を返す限り足すので、実機が **67fa で 0 を返すとき**だけ足さずに stage 3 / `off_count=1` 相当へ進めればよい。
   **ただし 67fa が 0 を返す座標条件は decomp から確定できなかった**（§3）。

## 2. 複線の流れ（該当部分）

| 番地 | 内容 |
|---|---|
| `0x2c9ce`〜`0x2ca81` | 押した点から間隔を決める：`trunc(0xff6/(0xb26/0xc30*0xb4a2*px)+0.5)` で画素に丸め直し、`compare [0xff6] : [0x97c0]=99999.5`（ja なら履歴の近い値に寄せる、`[bp-0xba]`＝5 候補）。 |
| `0x2c8c6` / `0x2c8e2` | 打った間隔 `[bp-0x1fc]`：`> 0.0` かつ `< [0x97bc]=9999999.0`（mm）でなければ入力し直し（`0x2c693`）。 |
| `0x2cc46`〜`0x2ce00` | R の「前線と連続」条件（`notes/decomp-audit.md` 既出）。成立で `[bp-0x30]=1`、基準線の `rec+0x14 & 0xc0` で `-1`。 |
| `0x2dd3e` | `gap_units = [0xff6]/([0xb26]*[0xb4a2])`、押した側の v<0 なら符号反転（`6fd6`）。 |
| `0x2dfe4`〜`0x2e1fb` | 基準線を `1bb4:27ea` で座標系にし、(u=0,v=gap)→(x0,y0)、(u=線長,v=gap)→(x1,y1) を `rec[-0x9c..]` に作る。ペン `[0xa6a]`→+0x11、線種 `[0xa6c]`→+0x10、レイヤ `[0xb310]`→+0x12。 |
| `0x2e255` | `[bp-0x30]==0`（普通の複写）なら `0x2e3c3`：**`lcall 11f2:67fa`（0x2e3d3）→戻り値無視→`[bp-0xdc]=1`（0x2e3fa）**→`0x2e541` 描き直し。 |
| `0x2e218`〜`0x2e36b` | `[bp-0x30]≠0`（前線と連続）：前の複写と `1bb4:3cd1` で交点、`call 0x2ab80`（ovl7 先頭、端をクランプして 67fa=`0x2ad9f`）を 2 回。ここも座標窓の検査は無く、クランプは `[0x9798]=0.0` と線長だけ。 |
| `0x2ddea`〜`0x2de16` | 基準線の `rec+0x14` に 0x40/0x80（2線 RR 等が付ける印）があると `[bp-0x30]=-1`、複写は `call 0x2adb8`（対の線を作る別処理）。SAMPLE0 の線は `rec+0x14=0` なのでここへは来ない。 |

円・円弧の複写（`[bp-0x1f2]<0`）は `0x2e421`〜`0x2e541`：新半径 `[bp-0xd2]+gap` と `compare 0.001 : 半径`（DS:0x97a4=0.001）、失敗で行 1 の空文字列（`DS:0x1dc ""`）を出して戻る。これは円用で線とは無関係。

## 3. 「範囲」の定数は decomp のほかの場所にある（が複線では使われていない）

DGROUP に `-470 / -330` の float 対が複数あり、使用箇所は次のとおり（バイト列 `8d 1e <off>`＝`lea bx,[off]` 経由の読み出しを全オーバーレイで検索）：

| 場所 | 定数 | 判定 | 失敗時 |
|---|---|---|---|
| root `0x1c319`（view の原点クランプ、スクロール用） | DS:0x9398 `-470`、0x939c `470`、0x93a0 `-330`、0x93a4 `330` | 表示原点 `[0xc48],[0xc4c]` を `[-470, …]`、`[-330, …]` に押さえる | クランプのみ |
| ovl23（線・□の入力、`0x2e5c0`〜`0x2e695`） | DS:0xa1f4 `-470`、0xa1f8 `1200`、0xa1fc `-330`、0xa200 `1000` | 線の終点 x,y が **x∈[-470,1200]・y∈[-330,1000] を外れる**と `[0xc22]=1`、行 2 桁 20 に `DS:0x402 "計算不可"`（0x2e61f〜0x2e639）、`0x2bf15` へ戻る。**67fa（0x2e695）の前**に置かれた検査 | メッセージ＋戻り（線は足さない） |
| ovl17（２線 RR、`0x2dff1`〜`0x2e03c`） | DS:0x9d20 `-470`、0x9d24 `-330`、上限 `[bp-0x52]=(0x1b3e-0xa5c)+0x1d6`（＝表示幅+470）、`[bp-0x54]=(0xa60-0xa5e)+0x14a`（＝表示高+330） | 交点 x∈[-470, W+470)、y∈[-330, H+330) | `[0xc22]=1`、行 2 桁 18、メッセージ（文字列番号は `0x474d` 付近の `jmp 0x2de0f` 先、未特定） |
| ovl4（面取、`0x2aeae`〜`0x2af13`） | DS:0x962c `-470`、0x9630 `-330`、上限は ovl17 と同形 | trim 後の端点 | `範囲外`(DS:0x28b2)、桁 18（notes/chamfer-decomp.md:37） |
| ovl7 `0x2f7da`〜`0x2f82a`、`0x2f9f1`〜 | DS:0x9800 `2000.0`、0x9804 `-1000.0` | 2 本の交点 X,Y が **(-1000, 2000)** の内側でなければ角つなぎをしない | 黙って次へ（`0x2f82c`）。複線関数の外（`0x2e58a` 以降の別処理） |

**複線の観測（上の辺の複写 y=1884.05 は拒否、左の辺の複写 x=-1146.108〜-1267.108 は受理）はこのどの窓とも一致しない**：
* ovl23 の窓 y≤1000 なら上の辺は拒否されるが、x≥-470 だと左の辺（-1146）も拒否されるはず（実機は受理）。
* ovl7 の `(-1000,2000)` だと上の辺 1884 は受理、左の辺 -1146 は拒否。逆。
* 単位も混ざる：ovl23/17/4 の `-470`/`W+470` は描画単位（ファイル座標）と画素数を同じ尺で比べている。SAMPLE0 は 1 単位 ≒ 0.57 画素ではなく表示倍率 `[0xc30]` を掛けた画素なので、
  座標そのものを画素窓と比べているのではなく「窓の外へ出たら描けない」という意味づけだと読める【推】。

## 4. 不確かな点・次に確かめること

* 【未】実機が `11f2:67fa` で 0 を返す条件。decomp では長さ 0（ペン<0x5a）と容量不足しか見つからず、**座標が遠いという条件は読み取れていない**。
  `22b2:6cc6`（0x29786）・`22b2:7191`（0x29cb1）は MSC の浮動小数エミュレータの内部で、0x185d3 の長さ 0 判定が極端な値でどう振る舞うかは未検証。
* 【推】拒否が実は容量不足経路（`これ以上描けません` を行 2 桁 18 に出し、直前の最後の線を新しい線で上書き）である可能性。座標で変わる要素が 43b1 に無いので薄いが、
  「previous last line が消える」観測とは矛盾しない。**実機で拒否された画面の行 2 に文字が出ているか**（あれば `これ以上描けません`）、
  **拒否直後・[ESC] 前に直前の最後の線が既に新しい線に置き換わっていないか**を見れば切り分けられる（エミュレータ側の仕事）。
* 閾値の絞り込みは実機の二分探索が必要：上の辺の複写 y を 1000〜1884 の間で、左の辺の x を -1267 より外側（-2000 前後）で測る。
  仮説候補（どれも decomp 上は未使用）：y>1000（ovl23 の窓の上限）／|座標|>2000（ovl7 後半の 0x9800）／ファイル座標の float→画素 変換の溢れ。
* ポートへの当座の入れ方（もし実機の拒否が確かなら）：`offset_line` で足す直前に判定を入れ、拒否なら足さず `c->off_count` 相当（段3の [ESC] が末尾の線を消す数）だけ 1 にして段3へ。
  判定式は上の測定が済むまで未確定。
