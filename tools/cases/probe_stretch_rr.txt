#     -> 右押しで選ぶと線切断待ち：「□ 線切断はマウス移動　　■【基準線指示は同位置マウス(R)】」

#   sh tools/probe.sh 6 r 220 157 r 220 157

#        帯の文言が「①指定点へ伸縮する対象線指示(ﾏｳｽ-L) ◇線切断(ﾏｳｽ-R)
#        【基準線指示(ﾏｳｽ-RR)】」から「○基準線へ伸縮する対象線指示(ﾏｳｽ-L) …」

# decomp（FUN_3ab8_2514、ovl02 3ab8:2514、file-linear 0x2d0c4〜0x2fa a9 付近）：
#   file-linear 0x2f6b4〜0x2f6dd 付近で、基準線と対象線のクロス積から求めた
#   交点距離の二乗（[bp-0x366]）を定数 [0x94bc] と比較し、jbe で 0x2f75d
#   （`計算不可`、DS:0x402、呼び出し `mov ax,0x14; mov ax,0x402; lcall 0xdef,0x23c5`）
#   へ分岐する。クロス積が 0 に近い（基準線が対象線と平行）ほど、除算
#   （0x2f5e0 の `[bp-0x1b6] = ... / ([bp-0x3b6] * [0x94ec])`）が発散して
#   距離の二乗が閾値を超える＝`計算不可` という組み立てだと読める
#   （＝基準線が対象線と平行のとき `計算不可`、という従来の予想と整合）。
#   ただし sprintf の引数の対応（どちらの文字列がどちらの %s か）や、
#   成功したときの実際の幾何（対象線をどちらの端からどちら向きへ伸ばすか、
#   1bb4:61b0 / 1bb4:5bf3 の正確な役割）は時間切れで確定できていない——
#   実装は見送り、ここは state machine（RR 検出とモード切替）のみ。
